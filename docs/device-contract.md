# 家庭设备工具契约

规范状态：`PROPOSED`。状态术语与维护人见[文档地图](index.md)。

本文是家庭设备工具的统一语义与后端适配边界的 Authority（权威位置）。系统职责见[软件架构](overview.md)；SimuHome 的运行与验证说明见[本地验证](simuhome.md)。

## 设计目标

Agent 面向稳定的家庭设备能力进行推理和调用。仿真平台与真实设备平台实现同一份上层契约，使运行循环、任务编排与实验中的目标判断可以复用。

职责分为三个边界：

| 边界 | 应承担的职责 |
| --- | --- |
| AgentRunner | 调用模型、分发已注册工具、接收结果、继续或结束运行 |
| 家庭设备工具 | 定义模型可见的参数和结果语义，按实际设备能力执行操作 |
| HomeBackend | 提供规范化的房间、设备、能力、状态与操作接口，完成平台标识和协议映射 |

SimuHomeBackend 是仿真验证后端。后续真实设备后端按同一契约接入，平台差异集中在适配器中。MCP 可以承载这些工具的发现与调用；设备语义由本文定义。

## 模型可见工具

第一组统一能力覆盖设备发现、状态查询和电源操作。新增能力按相同方式明确参数、适用设备、状态含义及完成证据。

| 工具 | 输入 | 应表达的结果 |
| --- | --- | --- |
| `get_rooms` | 无 | 可用房间及其真实标识 |
| `get_room_devices` | `room_id` | 该房间内的设备标识 |
| `get_device_capabilities` | `device_id` | 设备实际支持的能力及其可读、可写属性 |
| `get_device_state` | `device_id` | 已支持能力的当前状态和证据来源 |
| `set_device_power` | `device_id`、`on: bool` | 请求的电源状态、执行反馈与回读状态 |

`power` 统一表达设备的开关状态，值为布尔类型。后端应从实际设备结构识别该能力，并从设备状态读取当前值。对未支持的设备能力、缺失状态和失败操作，应返回明确错误，使调用方能继续处理。

### 统一结果字段

工具成功返回 `ok=true` 和规范化 `response`；失败返回 `ok=false` 与 `error`。后端错误同时保留稳定错误代码和实际反馈。后端提供的附加元数据和原生证据供来源追溯，决策使用规范能力与状态字段。

| 结果 | 规范字段 |
| --- | --- |
| 房间发现 | `rooms[]` 中的 `room_id` |
| 设备发现 | `room_id`、`devices[]` 中的 `device_id` |
| 能力描述 | `device_id`、`capabilities.power.readable/writable` |
| 当前状态 | `device_id`、`state.power`、`evidence_source` |
| 电源设置 | 当前状态字段、`requested_power`、`confirmed`、单独的 `command` 应答证据 |

电源命令已获应答但回读失败或不匹配时，错误保留已执行命令及可用状态证据。调用方应据此查询或解释当前进度，不能从“未确认”推断命令没有执行。

## 后端接口

`HomeBackend` 提供 `list_rooms`、`list_devices`、`get_device_capabilities`、`get_device_state`、`set_device_power`。家庭工具通过该接口访问设备平台；工具定义、模型上下文和运行循环使用统一语义。

后端应处理以下映射：

- 标识：将上层房间与设备标识对应到平台中的实际对象。
- 能力：从平台发现结果生成规范化的能力描述。
- 操作：将统一动作转换为平台支持的命令或服务调用。
- 状态：将平台属性转换为统一状态，并保留观测来源。
- 错误：保留操作失败和确认失败的事实，向上层提供可处理的信息。

当前 SimuHomeBackend 根据设备结构确定 OnOff 端点，再把 `on=true/false` 转换为 `On/Off`。后续 Home Assistant 后端需要映射真实实体标识、相应服务和上报状态；其实现与设备支持范围由真实接入实验验证。

## 执行与证据

工具应分别表达命令应答、设备状态和环境观测。状态确认只说明观测到的值与本次请求相符，其证据层次应明确：

| 证据 | 可以支持的结论 |
| --- | --- |
| 命令应答 | 后端受理或处理了命令 |
| 模拟设备状态 | 模拟器中的设备状态符合请求 |
| 真实设备上报状态 | 实体设备报告了相应状态 |
| 环境传感器观测 | 所观测的环境指标发生相应变化 |

SimuHome 回读标注为 `simulated_device_state`。例如，灯的模拟开关值为 `true`，可以作为仿真任务的状态证据；实际照明效果由真实设备和环境观测提供证据。

## 实验平台的职责

实验入口准备场景、调用被测运行系统并独立核验结果。实验 Agent 按[名称目录约定](index.md#实验-agent-目录约定)组织，复用共享运行内核与统一工具实现；场景初始化、独立结果判定和观察界面由实验仓库管理。实验记录关联平台版本、Agent 名称、场景输入与被测源码版本。

本地验证先覆盖统一电源能力在 SimuHome 后端的实现。真实后端接入后，对相同的能力语义和状态断言开展对应实验，并记录实际设备特有的延迟、离线和反馈情况。
